# Focus & Cafe

家で勉強できない自分のために作った、Windows 用の生活管理アプリです。
次にやることをルーレットで決め、その日のノルマが終わるまでゲームと動画サイトを開けなくします。

最初の版（Python + Streamlit）は [time-management-app-2](https://github.com/so880/time-management-app-2) にあります。今の版は React と FastAPI で作り直し、家計簿・カレンダー・就活の管理を足しました。

## 作った理由

家だと全く勉強できませんでした。ゲーム（イナズマイレブン）と YouTube で1日8時間使ってしまった日もあり、
そのせいで実験レポートを徹夜で書くことになりました。さすがにこれは駄目だと思いました。

一方で、図書館や授業中の内職では集中できていました。
集中できないのは意志の問題というより環境の問題で、家にも「逃げ道がない状態」を作れば同じように集中できるはずだ、と考えました。

もう1つのきっかけは、「次に何をやるかを自分で選ぶと、楽なものを選んでしまう」ことです。
次の行動をランダムに決めれば迷う時間もなくなると思いつき、同じことをしているアプリが見当たらなかったので作り始めました。

## できること

- **ルーレット**：やることの候補から、次にやることを抽選します。期限の近いものや重点の項目は当たりやすくしています。
- **今日のノルマ**：その日の必須のタスクと習慣を決めます。習慣はタイマーで決めた時間やらないと完了になりません（自己申告では完了にできません）。
- **制限**：ノルマが終わるまで、ゲームの起動と動画サイトの表示を止めます。ゲームは名前ではなく、インストール場所や同じフォルダの部品で見分けます。
- **解除の審査**：どうしても解除が必要なときは理由を書いて申請し、AI が審査します。自分だけの判断では解除できません。回数と長さには上限があります。
- **記録**：勉強時間、生活の予定（大学の時間割・Google カレンダー）、家計簿、就活の日程を1つの画面で扱います。スマホからはブラウザのページで記録できます。

## 工夫したところ

### 制限を自分で外せないようにした

一番こだわったのは「制限を外せない」ことです。普段は PC の大きな画面で動画を見ていたので、
PC で見られなくすれば、スマホやタブレットに逃げることもあまりありませんでした。

自分で作ったアプリなので、その気になれば自分で外せてしまいます。そこで、次のように作りました。

- 制限を弱める設定の変更（キーワードを消す、習慣を短くするなど）は、ノルマを終えるまで受け付けない
- 制限をオフにしても、その日だけで、翌日には自動でオンに戻る
- 制限を見張る仕組みが止まったり、データが読めなかったりしたら、解除ではなく制限する側に倒す

さらに、AI にコードを点検させたところ、タイムゾーンを変える、ゲームの実行ファイルの名前を変える、
カレンダーに偽の予定を入れる、といった抜け道が見つかったので、テストを書いてから1つずつふさぎました。

### 入力中の文字が勝手に確定する問題

制限の見張りを止められないように、数秒ごとに「止まっていたら起こし直す」処理を入れたところ、
起こすたびにコマンドの窓が一瞬開いて画面のフォーカスを奪っていました。
そのせいで、日本語を入力している途中の文字が変換される前に確定してしまう、という問題が起きました。
窓を出さずにプログラムを起動する方法に切り替え、起動の処理を1か所にまとめて直しました。

### UI

ここは今も悩んでいます。自分は毎日使っているので使い方が分かりますが、
初めて見た友人からは「タイトルの文字が小さい」「影がなくて違和感がある」などと言われました。
今は、Apple のデザインのガイドラインを基準に、画面を作り直しています。

## 技術

- 画面：React（Vite）
- 本体：Python（FastAPI）、SQLite（SQLAlchemy）
- 制限：Python のバックグラウンドの処理（psutil でプロセスを監視、前面のウィンドウのタイトルで動画サイトを判定）
- スマホ・Google カレンダー連携：Google Apps Script
- AI：Gemini API（解除の審査、家計の判定）
- テスト：pytest

## AI の使い方について

コードの大部分は AI（Claude など）に書かせています。
何を作るか、どこまで厳しくするか、どの抜け道をふさぐかは自分で決め、AI に伝えて、出てきたものを使ってみて直す、を繰り返しています。
途中からは、セキュリティ・不具合・読みやすさの観点で AI にコードを点検させ、見つかった問題をテストを書いてから直すようにしました。
